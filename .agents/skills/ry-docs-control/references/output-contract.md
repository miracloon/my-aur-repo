# 成文约束与格式规范

> 纯查询手册——在准备生成或扩写文档内容时查阅。
> 本文件只包含跨文档通用的规则。各文档专属的写作指导、自检标准见对应的 `assets/*.example.md`。

---

## 正文准入标准

内容只有满足以下**至少一条**时，才值得写入控制文档：

- [ ] 会长期改变 AI 的判断
- [ ] 会改变文档边界或规范归属
- [ ] 会改变后续协作、开发或维护方式
- [ ] 若 AI 不知道这一点，后续很容易做错、越界或漂移

**不是因为"问过了"就该写进去，也不是因为"答过了"就值得占用正文篇幅。**

---

## 成文约束

| 约束 | 说明 |
|------|------|
| 按主题组织 | 不按对话顺序 |
| 结论为主 | 背景与依据作为结论的从属说明 |
| 陈述句 | 不用问答体、聊天体、会议纪要体 |
| 未稳定的不入正文 | 进入 `【待裁决】`，不伪装成结论 |
| 不硬补栏目 | 模板有栏目不代表现在就要填满 |
| 高控制价值 | 追求"对 AI 判断有用"，不追求字数或覆盖感 |
| 优先结构化表达 | 默认用表格和列表陈述事实；仅在需要解释因果关系时用短叙述（2-3 句话） |

---

## 长度与密度参考

以下为各文档的典型体量参考。不是硬性限制，而是自检触发器——超出时应审视是否职责越界。

| 文档 | 参考范围 | 超出时应检查 |
|------|---------|------------|
| AGENTS.md | 30–80 行 | 是否在入口文档中替代了核心文档承担正文 |
| INTENT.md | 50–150 行 | 是否混入了操作步骤或结构细目 |
| ARCHITECTURE.md | 60–200 行 | 是否复制了 INTENT 的理由、WORKFLOW 的动态流程、SPEC 的目录结构或模块内部细节 |
| WORKFLOW.md | 60–200 行 | 是否写成了命令教程 |
| SPEC.md | 60–200 行 | 是否混入了设计意图说明 |
| MODULE 文档 | 30–150 行 | 是否混入了项目级信息，是否粒度过细（应对齐 SPEC 的模块划分） |

各文档更详细的写作指导和自检标准，见对应的 [assets/*.example.md](../assets/)。

文档结构的治理策略（栏目索引表、`##` 锁定规则、模块拆分、结构变更申请）见 [structure-contract.md](structure-contract.md)。
