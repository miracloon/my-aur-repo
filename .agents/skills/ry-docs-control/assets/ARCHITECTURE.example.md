【文档定位】
ARCHITECTURE.md 是按需创建的全局逻辑架构文档。只有系统的组件模型、职责、依赖、接口、数据所有权或跨模块不变量已经形成独立理解和维护边界时才创建。
它回答“这个系统在逻辑上是什么”，不因为项目代码量大就自动存在。

【核心职责】
提供项目级逻辑组件地图，使 AI 在进入具体目录或模块前理解主要组件各自负责什么、彼此怎样依赖、数据由谁拥有，以及哪些系统级边界不能被局部实现破坏。

【与其他文档的边界】
- INTENT.md：记录架构驱动、重大取舍及为什么这样选择
- ARCHITECTURE.md：记录当前成立的全局逻辑组件模型和不变量
- WORKFLOW.md：记录请求、数据和产物随时间怎样经过这些组件
- SPEC.md：记录逻辑组件在仓库中的物理映射、目录和维护规范
- modules/*.md：展开单个模块内部的意图、结构和运转细节

【写作原则】
- 以逻辑职责组织，不按目录树或运行步骤组织
- 只记录跨模块理解必需的稳定关系，不建立组件百科
- 同一事实只保留一个正文；其他文档使用摘要和链接
- 重大选择的必要理由可以简述，但完整取舍归 INTENT
- 不记录当前开发进度、候选架构或未验证实现
- 参考体量：60–200 行；超出时检查是否混入模块内部设计或完整运行流程

|------|-------|---------|
| 架构总览 | 系统上下文、逻辑分层或全局组件关系 | 项目目标、目录树、逐步运行流程 |
| 组件与职责 | 主要逻辑组件、职责、所有权和公开边界 | 模块内部实现、文件清单 |
