# AI_GLOBAL_PREFS 模板与指南

> 本文件是 `AI_GLOBAL_PREFS.md` 的模板和填写指南。
> 实际的偏好文件位于 skill 根目录：`ry-docs-control/AI_GLOBAL_PREFS.md`。

---

## 定位

AI_GLOBAL_PREFS.md 是用户维护的**跨项目全局偏好种子文件**。

- **不是**方法论文档（那是 references/ 的职责）
- **不是**项目特定的控制文档（那是 skill 的产出）
- **不是**目标项目中的文件（偏好在初始化时被分发到各控制文档，此文件本身不部署）
- **是**用户预填的既定事实，用于在控制文档初始化时跳过重复对齐

## 工作机制

1. 用户在 skill 内维护此文件，记录跨项目稳定的偏好和约束
2. **仅在初始化场景**，AI 读取此文件。更新和审阅场景不加载（偏好已在初始化时分发到项目控制文档中）
3. 文件中的内容被视为已确认事实，对齐阶段不重复追问
4. Phase 3 落文时，AI 根据 matrix-boundaries 将各条偏好归入项目对应的控制文档
5. 实际开发时，AI 从项目控制文档中读取，不依赖 skill 内部文件

## 优先级

- 用户当前明确裁定 > 已确认的项目需求 > 本文件 > AI 推断
- 项目需求与全局硬性约束冲突时，不静默选择一方，交给用户裁决；普通偏好由项目已确认需求覆盖

## 格式

两个分类，纯陈述句列表：

```markdown
## 硬性约束

{跨项目默认视为必须遵守的约束；除非用户当前明确改判，否则项目现状或 AI 推断不能覆盖。落文时通常归入 AGENTS.md。}

- {陈述句}

## 偏好与默认值

{通常成立但可被项目特定需求覆盖的偏好。落文时根据内容归入 INTENT / SPEC / WORKFLOW 等。}

- {陈述句}
```

## 维护建议

- 只写跨项目稳定成立的内容，不写单个项目的专属事实
- 发现新的跨项目偏好时随时补充
- 发现某条偏好不再跨项目适用时及时移除
- 保持简洁——陈述事实，不写背景和解释
