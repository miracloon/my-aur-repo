=== 写作指导（本区块不进入最终文档）===

【文档定位】
README.md 面向人类读者（用户、贡献者、路过的人），不面向 AI。
它的语气是"介绍一个产品"——自然、清晰、直接，不用营销腔、不用官话、
不用 AI 指令体。

【重要边界】
- README 不是控制面文档，不属于文档矩阵
- AI 不应在 README 中写面向 AI 的行为规则
- README 和 INTENT 的重叠区（"项目是什么"）需要注意语气区分：
  INTENT 写"设计意图和取舍"（面向 AI），README 写"产品介绍和使用"（面向人）

【重要性排序】
控制文档（INTENT/SPEC/WORKFLOW/AGENTS）>> README >> CLAUDE
README 比 CLAUDE 重要得多，但远不如控制文档。AI 不应在 README 上投入
主要精力和注意力。

【三个更新场景及边界】

| 场景 | 触发条件 | 边界约束 |
|------|---------|---------|
| 初始化配套 | 用户明确把 README 纳入初始化交付 | 控制文档完成后再生成；内容从控制文档“蒸馏”为面向人类的版本 |
| 按需更新 | 用户明确要求更新 README | 不在更新控制文档时顺手更新 README；只做用户要求的修改 |
| 完整对齐配套 | 用户明确要求控制面与 README 一并全面对齐 | 以现有 README 为起点，参照当前控制文档重新整理 |

**关键约束**：AI 不应主动更新 README，只在用户明确要求时才操作。

【已有 README 的项目】
- 初始化时，README 是高价值信息源——主动读取、提取有价值的项目信息
- README 中信息的吸纳优先级低于用户直接告知的事实
- README 的整理/重写排在控制文档之后

【自检清单】
生成或更新 README 后：
- [ ] 语气是否自然、面向人类？（不是 AI 指令体、不是营销腔）
- [ ] 是否只包含面向用户/读者的信息？
- [ ] 是否避免了重复控制文档中的 AI 行为规则？
- [ ] 是否简洁？README 不需要覆盖所有细节
