# AI 全局偏好

> 本文件中的内容是跨项目的既定事实。
> 仅在**初始化场景**读取，落文时写入项目对应控制文档。更新和审阅场景不加载本文件。
> 项目中用户当前的明确裁定可覆盖本文件；硬性约束不能被 AI 或项目现状静默弱化，冲突时应显式交给用户处理。

## 硬性约束

- 禁止使用系统 python，需要使用 python 时，仅允许使用 uv 管理的虚拟环境，虚拟环境默认目录应和项目一致
- 使用简体中文回复

## 偏好与默认值

- 偏好破坏式、不向后兼容的更新（已用 git 管理）
- 拒绝兜底式/补丁式方案：问题应从根源优雅解决，而非用 fallback 或 workaround 掩盖。宁可留空（`pass` + TODO）显式标记未完成，也不接受"能跑就行"的最小应付实现

## 阶段性开发集成

- 项目实际采用 `docs/development/` 下的 `DEV_WORKFLOW.md`、`active/<identifier>/` 和 `history/<identifier>/` 时，AGENTS.md 应提供最小导航并说明信息身份：Design 表达意图与决定，Plan 表达可选执行路径，任务定义表达交接范围，State 表达当前工作状态；它们都不能单独证明功能已经实现或验证
- 阶段性成果经一致性收束和项目现实核验后，才按需进入长期治理文档；不把阶段文档整体复制成项目当前事实
